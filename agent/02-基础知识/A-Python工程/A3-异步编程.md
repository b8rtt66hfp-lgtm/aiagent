# A3 · 异步编程

> 对应关卡：L2
> 面试权重：极高。Agent 服务 90% 的时间在等模型和接口返回，**不会异步就等于不会写 Agent 服务**。

---

## 1. 一句话结论

**异步不是"更快"，而是"等待时不占着线程"。** 一个请求等 3 秒 LLM 返回，同步写法会卡死线程；异步写法这 3 秒可以去服务其他请求。面试考的是：你能不能在生产代码里正确使用它，而不是写出"看起来 async 但实际是串行"的代码。

---

## 2. 概念

### 2.1 为什么 Agent 必须异步

一次 Agent 任务的时间构成：

```
调模型 2s + 调工具 0.5s + 调模型 2s + ...
```

几乎全是 **IO 等待**，CPU 基本闲着。同步模型下，一个进程同时只能服务一个请求；异步模型下，成百上千个请求可以挂在同一个线程上。

### 2.2 三个核心词

| 概念 | 通俗解释 |
| --- | --- |
| 事件循环（Event Loop） | 一个调度员，谁准备好了就去执行谁 |
| 协程（Coroutine） | `async def` 定义的函数，调用它不会立即执行，返回协程对象 |
| `await` | "我要等了，调度员你去干别的，好了再叫我" |

关键理解：**`await` 是主动让出控制权**。没有 `await` 的 async 函数，和普通函数没区别。

### 2.3 并发执行：三种写法

```python
# 1. 串行（错误示范，总耗时 = 3 × 2s）
for url in urls:
    await fetch(url)

# 2. gather（最常用）
results = await asyncio.gather(*[fetch(u) for u in urls])

# 3. TaskGroup（3.11+，异常处理更清晰）
async with asyncio.TaskGroup() as tg:
    for u in urls:
        tg.create_task(fetch(u))
```

`gather` 与 `TaskGroup` 的差异（**高频面试题**）：

| | `gather` | `TaskGroup` |
| --- | --- | --- |
| 某个任务失败 | 默认立即抛出，其他任务**继续跑**（结果被丢弃） | 取消其余所有任务，最后抛 `ExceptionGroup` |
| 是否要用 `return_exceptions` | 需要，用 `True` 收集所有结果 | 不需要，统一在 `except*` 里处理 |
| 适用 | 想拿"部分成功"的结果 | 强一致，一个失败整体失败 |

### 2.4 超时与取消

```python
# 3.11+
try:
    async with asyncio.timeout(10):
        data = await fetch(url)
except TimeoutError:
    data = None

# 3.10 及以前
try:
    data = await asyncio.wait_for(fetch(url), timeout=10)
except asyncio.TimeoutError:
    data = None
```

取消不是"立刻停"，而是向协程抛 `CancelledError`，协程要在 `finally` 里清理资源（关闭连接、释放锁）。

### 2.5 并发控制：Semaphore

不对并发做限制，1000 个请求同时打向模型 API，结果就是被限流、超时、账单失控。

```python
sem = asyncio.Semaphore(10)

async def guarded(url):
    async with sem:
        return await fetch(url)
```

### 2.6 绝对不能阻塞事件循环

以下操作会卡住整个事件循环，所有并发请求一起卡死：

- `requests.get(...)`、`time.sleep(...)`
- 大文件同步读写
- 大量 CPU 计算

处理方式：

```python
# IO 阻塞 → 丢到线程池
data = await asyncio.to_thread(blocking_io_func, arg)

# CPU 密集 → 进程池
loop = asyncio.get_running_loop()
result = await loop.run_in_executor(process_pool, cpu_heavy, arg)
```

### 2.7 GIL 一句话解释

CPython 的 GIL 让同一时刻只有一个线程执行 Python 字节码，所以**多线程不能并行做 CPU 计算**；
但线程在等 IO（网络、磁盘）时会释放 GIL，所以**多线程适合 IO 密集**。
协程比线程更轻，一个线程能跑成千上万个协程，所以 Agent 服务首选 asyncio。

### 2.8 异步流式输出

LLM 的流式返回天然是异步生成器：

```python
async def stream_tokens():
    for token in ["你", "好", "，", "世界"]:
        await asyncio.sleep(0.1)   # 模拟网络
        yield token


async def main():
    async for token in stream_tokens():
        print(token, end="", flush=True)
```

`async for` 配合 `yield`，就是 SSE 流式接口的核心。

## 3. 最小可运行代码

### 3.1 并发 + 超时 + 限流（生产骨架）

```python
import asyncio
import httpx


async def fetch(client: httpx.AsyncClient, url: str, sem: asyncio.Semaphore) -> dict | None:
    async with sem:                                  # 限流
        try:
            async with asyncio.timeout(10):          # 超时
                resp = await client.get(url)
                resp.raise_for_status()
                return resp.json()
        except (TimeoutError, httpx.HTTPError) as e:
            print(f"[warn] {url} 失败: {e}")
            return None                              # 单点失败不拖垮整体


async def main(urls: list[str]):
    sem = asyncio.Semaphore(10)
    async with httpx.AsyncClient(
        timeout=httpx.Timeout(10.0, connect=3.0)
    ) as client:                                     # 复用连接池
        tasks = [fetch(client, u, sem) for u in urls]
        results = await asyncio.gather(*tasks)
    ok = [r for r in results if r]
    print(f"成功 {len(ok)}/{len(urls)}")
```

### 3.2 gather 的异常处理

```python
results = await asyncio.gather(*tasks, return_exceptions=True)
for r in results:
    if isinstance(r, Exception):
        print("失败：", type(r).__name__, r)
    else:
        print("成功：", r)
```

不加 `return_exceptions=True`，第一个异常就会让 `gather` 抛出，**其他任务仍在后台跑，但结果拿不到**——这是资源泄漏的常见原因。

### 3.3 FastAPI 流式接口

```python
from fastapi import FastAPI
from fastapi.responses import StreamingResponse

app = FastAPI()


async def gen_reply(question: str):
    async for token in call_llm_stream(question):
        yield f"data: {token}\n\n"        # SSE 格式：data + 空行


@app.get("/chat")
async def chat(q: str):
    return StreamingResponse(gen_reply(q), media_type="text/event-stream")
```

两个要点：`async def` 保证不阻塞；生成器里的异常要在推流前捕获，否则连接直接断掉。

### 3.4 不要这样写

```python
@app.get("/bad")
async def bad(q: str):
    resp = requests.get(f"https://api.example.com?q={q}")   # 阻塞事件循环
    time.sleep(1)                                           # 同样阻塞
    return resp.json()
```

正确：

```python
@app.get("/good")
async def good(q: str):
    async with httpx.AsyncClient() as client:
        resp = await client.get("https://api.example.com", params={"q": q})
    return resp.json()
```

## 4. 常见坑

1. **`coroutine was never awaited`**：调用 `foo()` 忘了 `await`，协程根本没执行。
2. **在运行中的事件循环里调 `asyncio.run()`**：Jupyter、FastAPI、已启动的 loop 里都会报 `RuntimeError: This event loop is already running`。要用 `await` 或 `nest_asyncio`（仅调试）。
3. **async 函数里写同步阻塞调用**：最隐蔽的性能杀手，压测时表现为"并发上不去"。
4. **`create_task` 不保存引用**：任务可能被垃圾回收，中途消失。要存到集合里并在结束时 `await`。
5. **`gather` 不处理异常**：一个失败，整体 500，其他结果全丢。
6. **共享 `AsyncClient` 生命周期写错**：每次请求新建 client = 每次新建连接池，性能极差；应在应用启动时创建、关闭时释放。
7. **超时只设一层**：单请求 10s，重试 3 次就是 30s，外层还要有总预算。
8. **忽略取消**：`CancelledError` 不是普通异常，不要用 `except Exception` 吞掉，否则任务无法正常取消。

## 6. 参考答案与自测标准

### 练习 1 答案

- A 是（网络 IO）
- B 不必（2KB 极小，同步反而更简单；如果频繁读可考虑缓存）
- C 不该用 async（CPU 密集，应该用进程池或算法优化；async 不会加速计算）

- E 不该直接 async 调 `requests`（它本身同步），应换 `httpx.AsyncClient`；或用 `to_thread` 兜底

**自测标准**：判断依据是"是否在等 IO"，不是"函数重要不重要"。

### 练习 2 答案

```python
import asyncio
import httpx

async def fetch_one(client, url, sem):
    async with sem:
        try:
            async with asyncio.timeout(5):
                r = await client.get(url)
                r.raise_for_status()
                return r.json()
        except Exception as e:
            return e

async def main(urls):
    sem = asyncio.Semaphore(10)
    async with httpx.AsyncClient() as client:
        results = await asyncio.gather(*(fetch_one(client, u, sem) for u in urls))
    success = sum(1 for r in results if not isinstance(r, Exception))
    print(f"成功 {success}/{len(urls)}")

asyncio.run(main([...]))
```

**自测标准**：限流、超时、异常隔离、复用 client，四件事都做到。

### 练习 3 答案

- `gather` 默认：第一个异常立刻抛给调用方，其他任务继续在后台跑，结果丢弃。
- `TaskGroup`：任一任务失败会取消同组其他任务，等全部结束后抛 `ExceptionGroup`。

刻意选 `gather(return_exceptions=True)` 的场景：批量任务里"部分失败可以接受"，比如批量摘要 100 篇文章，失败了就跳过，不能因为一篇失败全部重来。

**自测标准**：能说出"部分成功"与"全有或全无"的语义差异。

### 练习 4 答案

问题：`time.sleep` 和 `requests` 都是同步阻塞，会卡死事件循环，async 完全失效。

```python
import asyncio
import httpx

async def summarize(text: str) -> str:
    async with httpx.AsyncClient(timeout=10) as client:
        resp = await client.post(API_URL, json={"text": text})
        resp.raise_for_status()
        return resp.json()["summary"]
```

如果必须用同步库：`await asyncio.to_thread(blocking_call, text)`。

**自测标准**：能说出"async 里混同步 = 白写"。

### 练习 5 答案

```python
import asyncio
from fastapi import FastAPI
from fastapi.responses import StreamingResponse

app = FastAPI()


async def stream_text(text: str, size: int = 5):
    for i in range(0, len(text), size):
        await asyncio.sleep(0.05)
        yield text[i:i + size]


@app.get("/stream")
async def stream(q: str):
    async def event_gen():
        async for chunk in stream_text(q):
            yield f"data: {chunk}\n\n"
        yield "data: [DONE]\n\n"
    return StreamingResponse(event_gen(), media_type="text/event-stream")
```

**自测标准**：知道 SSE 的 `data: xxx\n\n` 格式，以及结束标记。

### 练习 6 答案

输出：

```
start 1
main done
```

**不会**打印 `end 1`。原因：`main` 结束时 `asyncio.run` 关闭事件循环，未完成的 `create_task` 被取消。任务是"后台执行、不等待"的，必须显式 `await task` 或用 `gather` 等它完成。

**自测标准**：能说出"create_task 只是安排执行，不保证完成"。

## 7. 面试问法

| 面试官可能这么问 | 你要答到的点 |
| --- | --- |
| 为什么用 asyncio 而不是多线程？ | IO 密集、协程更轻、单线程无锁；CPU 密集才用多进程 |
| GIL 是什么？ | 同刻只有一个线程执行字节码；IO 等待会释放；所以线程适合 IO、进程适合计算 |
| gather 和 TaskGroup 区别 | 失败传播策略、取消行为、异常聚合方式 |
| 怎么限制并发 | Semaphore、队列、连接池上限；再说外部 API 的限流配额 |
| 怎么设置超时 | 单请求超时 + 重试 + 总预算三层；取消要清理资源 |
| async 函数里调同步代码会怎样 | 阻塞事件循环，所有请求卡住；用 to_thread 或换异步库 |
| 怎么实现流式输出 | async 生成器 + yield + StreamingResponse/SSE |
| 协程和线程的区别 | 用户态调度、协作式切换、开销小；线程是内核调度、抢占式 |
