# A2 · 类型与数据建模

> 对应关卡：L1 ~ L2
> 面试权重：高。Agent 项目里三个地方全靠它：**工具入参、LLM 结构化输出、接口请求响应**。

---

## 1. 一句话结论

**Agent 工程的本质是"让不可靠的自然语言，变成可靠的结构化数据"。** 类型系统就是那道关口：用 Pydantic 定义 schema → 约束模型输出 → 校验失败就重试。不会建模，就写不出稳定 Agent。

---

## 2. 概念

### 2.1 为什么 Agent 项目离不开类型

| 场景 | 没有类型会发生什么 |
| --- | --- |
| 工具入参 | 模型传了 `top_k="five"`，你的检索函数直接崩 |
| LLM 输出 | 返回的 JSON 少了字段，下游 KeyError |
| API 响应 | 第三方接口字段变了，线上静默出错 |
| 配置 | 环境变量没设，服务启动一半才报错 |

类型在这里不是"给 IDE 看的装饰"，而是**运行时校验 + 自动生成 schema**。

### 2.2 typing 基础（必须能读懂和写）

```python
from typing import Any, Callable, Literal, Optional

def search(query: str, top_k: int = 5) -> list[dict]:
    ...

# 现代写法（3.10+）
def find(name: str | None = None) -> dict[str, Any]:
    ...
```

要点：

- `Optional[X]` = `X | None`，**注意它不等于"可以不传"**，有默认值才可不传
- `Literal["a", "b"]` 适合枚举少量取值，会进入 schema，模型看到取值就知道怎么填
- `Any` 是逃生舱，用多了等于没有类型
- `Callable[[str], int]` 表示函数类型

### 2.3 dataclass：轻量数据容器

```python
from dataclasses import dataclass, field

@dataclass(frozen=True, slots=True)
class ToolCall:
    name: str
    arguments: dict = field(default_factory=dict)
```

- 自动生成 `__init__` / `__repr__` / `__eq__`
- `frozen=True` 不可变（可哈希，能放 set/做缓存 key）
- `slots=True` 省内存、防手滑加属性
- **可变默认值必须用 `field(default_factory=...)`**，直接写 `=[]` 会报错（dataclass 直接帮你拦住了 Python 的经典坑）

适合：内部传递的数据、不需要校验、追求轻量。

### 2.4 Pydantic：带校验的模型（重点）

```python
from pydantic import BaseModel, Field
from typing import Literal


class SearchArgs(BaseModel):
    query: str = Field(min_length=1, max_length=100, description="检索关键词")
    top_k: int = Field(default=5, ge=1, le=20, description="返回条数")
    mode: Literal["vector", "keyword", "hybrid"] = Field(
        default="hybrid", description="检索模式"
    )
```

三个能力，一个比一个重要：

1. **自动校验**：`SearchArgs(query="", top_k=99)` 直接抛 `ValidationError`
2. **自动生成 JSON Schema**：`SearchArgs.model_json_schema()`，直接就是模型 function calling 需要的参数定义
3. **自动类型转换**：`"5"` 会转成 `5`（宽松模式），但 `"five"` 会报错

自定义校验：

```python
from pydantic import field_validator


class Query(BaseModel):
    text: str

    @field_validator("text")
    @classmethod
    def not_blank(cls, v: str) -> str:
        v = v.strip()
        if not v:
            raise ValueError("不能为空")
        return v
```

多个字段互相约束用 `@model_validator(mode="after")`。

### 2.5 从模型到工具 schema

```python
SearchArgs.model_json_schema()
# {
#   "properties": {...},
#   "required": ["query"],
#   "title": "SearchArgs",
#   "type": "object"
# }
```

```python
tools = [{
    "type": "function",
    "function": {
        "name": "search_docs",
        "description": "在企业知识库中检索资料。用户询问内部制度、流程时使用。",
        "parameters": SearchArgs.model_json_schema(),
    },
}]
```

**这就是"类型即接口"**：模型看到的参数结构，和你代码里的校验模型是同一份定义，不会漂移。

### 2.6 TypedDict：给字典加结构，不增加运行时开销

```python
from typing import Annotated, TypedDict
import operator


class AgentState(TypedDict):
    messages: Annotated[list, operator.add]   # LangGraph 里表示"追加"
    step: int
```

适合 LangGraph 的 State：它本质还是 dict，运行时零开销，但静态检查能发现拼错 key。

### 2.7 Protocol：面向接口编程

```python
from typing import Protocol


class LLMClient(Protocol):
    async def chat(self, messages: list[dict], temperature: float = 0.0) -> str: ...


def run_agent(client: LLMClient) -> str:
    ...
```

好处：测试时传一个假的 `FakeClient` 就行，不需要继承、不需要 mock 框架。这是**可测试性**的关键设计。

### 2.8 Enum 还是 Literal？

- 只在模型/函数签名里用 → `Literal`，轻量、schema 友好
- 需要在代码里引用常量、做遍历 → `Enum`

## 3. 最小可运行代码

### 3.1 解析 LLM 工具参数（带错误语义）

```python
import json
from pydantic import ValidationError


def parse_args(raw: str) -> SearchArgs:
    """把模型返回的 arguments 转成受校验的对象。"""
    try:
        data = json.loads(raw)
    except json.JSONDecodeError as e:
        raise ValueError("参数不是合法 JSON，请重新生成") from e

    try:
        return SearchArgs.model_validate(data)
    except ValidationError as e:
        # 转成模型能读懂的提示，而不是一坨 traceback
        raise ValueError(f"参数不符合要求：{e.errors()[0]['msg']}") from e
```

### 3.2 嵌套模型 + 输出

```python
class Todo(BaseModel):
    owner: str
    task: str
    deadline: str | None = None


class MeetingNotes(BaseModel):
    topic: str
    decisions: list[str] = Field(default_factory=list)
    todos: list[Todo] = Field(default_factory=list)


notes = MeetingNotes.model_validate({
    "topic": "周会",
    "todos": [{"owner": "张三", "task": "出方案"}],
})
print(notes.model_dump_json(exclude_none=True))
print(notes.todos[0].owner)   # 属性访问，不是 notes["todos"][0]["owner"]
```

### 3.3 配置模型（启动即校验）

```python
from pydantic import Field
from pydantic_settings import BaseSettings


class Settings(BaseSettings):
    llm_api_key: str = Field(alias="LLM_API_KEY")
    model_name: str = "gpt-4o-mini"
    max_steps: int = Field(default=8, ge=1, le=30)

    model_config = {"env_file": ".env", "extra": "ignore"}


settings = Settings()   # 缺 key 直接启动失败，而不是运行到一半才炸
```

## 4. 常见坑

1. **Pydantic v1 与 v2 混用**：`parse_obj` → `model_validate`，`Config` → `model_config`，`@validator` → `@field_validator`。网上的教程一半是 v1。
2. **`Optional[str]` 却当成"可以不传"**：没有默认值时它仍然是必填。
3. **校验过严导致模型频繁失败**：`query` 限制 10 字以内，模型每次都给 12 字，你的 Agent 就会一直重试。约束要贴合真实输出分布。
4. **只用 `model_dump()` 返回给前端**：含 `datetime`、嵌套模型时可能不可序列化，用 `model_dump(mode="json")`。
5. **schema 太大**：几十个字段塞进工具定义，模型选择困难、token 暴涨。**一个工具只做一件事**。
6. **`Any` 泛滥**：类型检查形同虚设，等于没写。
7. **可变默认值**：Pydantic 会深拷贝默认值，相对安全，但 dataclass 必须 `default_factory`。
8. **把校验异常直接抛给模型**：报错信息要能指导模型"怎么改"，而不是 `validation error for SearchArgs`。

## 6. 参考答案与自测标准

### 练习 1 答案

问题：

1. `age` 没有范围校验，负数也能过 → `Field(ge=0, le=150)`
2. `tags` 用可变默认值（Pydantic 会深拷贝，能跑，但语义上是共享默认值的写法，应改为 `Field(default_factory=list)`）
3. 缺少 `description`，如果这个模型要作为工具 schema，模型不知道该填什么

```python
class UserProfile(BaseModel):
    name: str = Field(min_length=1, description="用户姓名")
    age: int = Field(ge=0, le=150, description="年龄")
    tags: list[str] = Field(default_factory=list, description="标签")
```

**自测标准**：能说出"校验 + 描述"是工具模型的两个必备部分。

---

### 练习 2 答案

```python
from datetime import date
from typing import Literal
from pydantic import BaseModel, Field


class FlightQuery(BaseModel):
    from_city: str = Field(min_length=1, max_length=20, description="出发城市，如 北京")
    to_city: str = Field(min_length=1, max_length=20, description="到达城市，如 上海")
    date: date = Field(description="出发日期，格式 YYYY-MM-DD")
    cabin: Literal["economy", "business"] = Field(default="economy", description="舱位")
    passengers: int = Field(default=1, ge=1, le=9, description="乘客人数")
```

`Field` 的作用：`description` 给模型看，`ge/le/min_length` 给校验用，`default` 减少模型必须填的字段。

**自测标准**：类型选 `date` 而不是 `str`，让 Pydantic 帮你校验日期格式。

### 练习 3 答案

```python
data = {"query": "报销流程", "top_k": "3"}
args = SearchArgs.model_validate(data)
# 默认 lax 模式下 "3" 会转成 3，成功

data = {"query": "报销流程", "top_k": "three"}
# 抛 ValidationError：Input should be a valid integer
```

期望行为：捕获 `ValidationError`，把错误摘要回传给模型重试一次，而不是直接 500。

**自测标准**：知道 Pydantic 默认宽松转换，以及"失败要转成可行动的错误信息"。

### 练习 4 答案

```python
from typing import Protocol


class LLMClient(Protocol):
    async def chat(self, messages: list[dict], temperature: float = 0.0) -> str: ...


class FakeClient:
    def __init__(self, reply: str):
        self.reply = reply
        self.calls = 0

    async def chat(self, messages, temperature=0.0) -> str:
        self.calls += 1
        return self.reply


async def run_agent(client: LLMClient) -> str:
    return await client.chat([{"role": "user", "content": "hi"}])
```

**自测标准**：能说出"Protocol 是结构化子类型，不需要显式继承"，以及"这样测试不需要真实 API 费用"。

---

### 练习 5 答案

- A：dataclass（内部轻量，不需要校验，`frozen` 还能做缓存 key）
- B：Pydantic（外部输入，必须校验，还要生成 OpenAPI）
- C：Pydantic（模型输出不可信，必须校验 + 兜底重试）

**自测标准**：判断依据是"数据是否跨信任边界"。

## 7. 面试问法

| 面试官可能这么问 | 你要答到的点 |
| --- | --- |
| 为什么用 Pydantic 不用 dict？ | 运行时校验、自动 schema、错误信息、IDE 提示；dict 出错要等下游 KeyError |
| 模型输出怎么保证结构？ | 用模型生成 schema + function calling/structured output + Pydantic 校验 + 失败重试 |
| dataclass 和 Pydantic 区别 | 轻量无校验 vs 校验+序列化+schema；内部用前者，边界用后者 |
| `Optional` 是什么意思 | `X | None`；不等于可省略，需要默认值 |
| 怎么设计好用的工具 schema | 字段少、描述写场景、枚举用 Literal、范围用 Field、必填尽量少 |
| TypedDict 有什么用 | 给 dict 静态结构，运行时零开销，适合 LangGraph State |
